# 假设驱动的漏洞挖掘

## 目标与输入
从当前目标的真实入口和信任边界推导可证伪假设，避免把漏洞清单逐项机械执行。先读取 `get_recon_context`；历史报告、组件指纹和方法论只提供方向，证据必须来自本目标。开局无需加载全部方法论。

## 建立入口—边界—假设矩阵
| 已观察事实 | 需要厘清的边界 | 下一篇方法论 |
|---|---|---|
| 登录、刷新、找回、角色切换 | 会话由谁签发、绑定、撤销 | session_management / auth_bypass |
| 外部身份提供方、授权回调 | 事务、客户端、用户与返回地址的绑定 | oauth_oidc / saml |
| 对象 ID、租户 ID、批量或导出 API | 主体—对象—操作—租户授权 | api_authorization / idor |
| Cookie 认证下的状态变更 | 请求是否确由当前用户发起 | csrf |
| 文件、文档、消息或序列化对象导入 | 外部数据是否进入解释器/对象恢复 | file_upload / xxe / deserialization |
| 查询、报表或筛选 | 值与查询结构是否隔离 | sqli / nosqli |
| 回调、预览、远程导入 | 目标服务端出站请求边界 | ssrf |
| JS、SourceMap、调试页面、存储资源 | 公开信息与受保护内容边界 | information_disclosure / cloud_assessment |
| 已有主机/云身份执行证据 | 实际身份、资源权限与环境边界 | 对应平台评估方法论，再 post_assessment |

通过 `list_vuln_playbooks(query, stage)` 检索。出现多个候选先依据真实入口选择，再按 name 精确读取；“注入”“后渗透”这种宽泛词不能直接确定技术路径。

## 选择下一步
优先验证“入口真实存在、前置身份具备、业务影响明确、可用最少测试消除不确定性”的假设。组件版本猜测、外部工具缺失、无法建立基线或需要超出范围的路径后置，并记录阻塞原因。不要为了追求高分而跳过身份、租户和证据核对。

每个假设记录：目标/入口、输入来源、预期约束、支持事实、反证条件、必要身份、最小动作、预期观察、实际观察和下一步。一次只改变一个关键条件；对照必须在相同身份、对象状态和时间窗口内有效。

## 根据结果分支
- 证据支持：用独立观察确认实际影响，转对应漏洞的修复和复测，必要时记录有证据的步骤。
- 结果否定：记录测试条件和覆盖范围；同一无效输入不要仅换编码反复重试，返回调用链/状态/前置条件分析。
- 无法判定：区分权限不足、工具限制、依赖不可达、响应截断和目标防护。补缺失观察或转其他已具备条件的入口，不把阻塞写成安全结论。
- 发现新边界：为新对象建立独立假设；知识关联不能自动成为已确认攻击链。

## 收尾产物
交付覆盖矩阵、确认问题、已排除假设、未覆盖项和证据索引。目标变化后重新核对基线，完成验证转 `post_assessment`，修复复测不能只重放原请求，还要验证合法业务。
