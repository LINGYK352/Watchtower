# API 对象、属性与功能授权

## 从入口到假设
已有真实业务 API、角色或租户信息。按“主体 × 租户 × 对象 × 操作 × 字段”建矩阵，区分对象越权、功能越权、字段过度暴露与批量赋值；列表、详情、批量、导出、异步任务和管理接口分别检查。

## 最小验证路径
用两个自有测试账户创建明确归属的对象。经 `browser_resources` 观察真实调用，用 `fetch_sourcemap` 辅助理解前端声明，但以后端回执为准。每次只变更一个边界条件；字段写入要通过独立读取确认持久化结果，不能把请求回显当成修改成功。

对角色和租户字段，先确认其是否由服务端管理；业务设计允许用户修改的字段不算批量赋值。权限判断在后端，前端隐藏按钮不能替代测试。

## 验证与反证
状态码相同、对象 ID 可猜、字段出现在 schema 中都不是越权证据。要证明当前主体本不应访问该对象/字段/功能且实际成功，排除共享对象、测试账户自带权限、缓存串读和空壳页面。

## 修复与复测
每个对象操作显式授权，使用字段允许列表和按角色的输出视图。复测合法操作、跨对象/跨租户拒绝、批量部分失败、异步任务取结果以及写后读取；清理测试对象。已确认点按实际影响报告，避免一个根因拆成多个重复漏洞。
