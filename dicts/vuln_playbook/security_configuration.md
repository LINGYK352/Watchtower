# Web 部署配置与错误处理

## 从站点结构发现入口
复用侦察结果、实际页面链接和资源引用核对反向代理、应用、管理端点、静态资源与错误页的边界。区分默认示例、健康检查、公开文档和管理功能，不凭路径名推断敏感程度。

## 最小验证流程
建立正常页面、已知不存在路径和受保护端点的对照，检查状态码、内容类型、重定向、缓存及主体内容。对已发现的目录列表、备份引用或错误信息核对是否包含不应公开的内容；不做无差别路径扫描。

## 验证与反证
SPA 通配路由与网关错误页可能让所有路径返回相同 200。OPTIONS 声明支持某方法不证明该方法能修改资源；Server 头可伪造，组件归属要独立确认。缺少安全头的影响依赖实际利用前提。

## 修复与复测
关闭无业务用途的调试/示例端点，限制管理面，统一错误脱敏和方法授权。复测业务页面、错误分支、静态资源和代理转发，确认合法健康检查仍可用。
