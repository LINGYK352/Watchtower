# OAuth / OIDC 认证流程评估

## 适用条件与输入
已观察到授权请求、回调或联合登录流程。先标明客户端、身份提供方、资源服务、浏览器和账户归属；区分 OAuth 授权与 OIDC 身份认证，不能只凭参数名称判断协议实现。

## 挖掘路径
以自有测试账户走通合法登录，记录授权事务与回调的绑定关系、允许的返回地址及最终服务端主体。围绕事务关联、授权码一次性使用、客户端绑定和令牌接收方建立独立假设。用另一个独立测试会话作对照，避免已有登录状态掩盖回调问题。

`browser_open`/`browser_resources` 辅助观察页面与实际请求；敏感授权材料只记摘要。需要协议端日志或客户端配置而无法获取时标注未覆盖，不把无法观测当成未实现保护。

## 验证与反证
只有最终应用会话绑定错误主体、受保护资源接受错误令牌，或回调将测试数据送到错误受信方，才支持相应边界缺陷。跳转异常、参数被反射和用户取消登录都不是接管证据；中间一步失败不能自动归因于 state 或 PKCE。

## 修复与复测
严格绑定授权事务、客户端和返回地址，按协议验证令牌签发方/受众/时效，使用适合客户端类型的保护机制。复测正常登录、取消/重试、过期/重复回调、并发登录及退出后的会话状态，清理测试授权。
