# Windows 独立桌面测试版

桌面窗口 v1.21.167-10 build2；本机界面/版本元数据167-10，Linux基础初始化介质v1.21.167-8。仅桌面独立副本，未正式发布。

## 交互契约

双击安装目录的 Watchtower.exe，入口读取 active.json，运行版本目录中的 WatchtowerDesktop.exe。程序显示默认最大化的独立 Windows 主窗口，自动启动/连接本机后台，准备完成后在同一窗口显示完整 Vue 工作台，没有地址栏，不启动外部浏览器。界面使用 WebView2 内嵌技术；后端仍是本机隔离的 Linux 服务，内部仍使用仅本机的 HTTP 通信。这并非全部改写为原生 Windows 控件。

167-8 及以前的 Tk 控制面板要求用户点击「打开工作台」跳浏览器，不能满足正常桌面程序入口要求，现已被内嵌窗口替代。原 Web 项目及 Vue 业务界面不改写，复用既有接口和路由。桌面界面版本与核心版本独立，不因窗口改造重打 Linux 初始化介质；portable_runtime.APP_VERSION 始终指定当前配套介质版本。

顶部「应用」菜单提供重新连接、安装 Windows 更新包、查看说明、停止后台并退出，以及关闭窗口并保留任务。关闭窗口不停止后台；显式停止会终止本测试实例中的任务。再次双击复用原窗口。用户状态和 WebView2 缓存在安装目录 state/webview 中，不混用系统浏览器的登录状态。

桌面运行需要 Windows WebView2 Runtime。本次物理机已有运行库，没有安装系统功能或重启 Windows；未安装该运行库的其他电脑需要另行准备，不能宣称覆盖所有 Windows 机器。

## 构建与本机更新

在独立副本创建 Python 虚拟环境，安装 requirements-build.txt，然后执行 windows_preview/build_desktop.py --build 2（后续改程序时递增build）。基础介质runtime/payload-v1.21.167-8.iso须保留；构建器从它生成前端基线缓存。构建器将 candidate、PyInstaller 中间产物和签名私钥保存在忽略的 validation/，生成本机签名差异更新包；不会推送 GitHub、分发网站或修改正式源。已有安装时不覆盖运行中的 EXE，由独立更新器校验签名、文件差异、真实 WebView2 渲染健康后再切换 active.json。167-8→167-9→167-10 build1/build2已在本机实际完成。

新安装本次所需完整 runtime/engine 资源仍由桌面目录保留。签名差异包更新桌面程序并携带前端差异，同一启动流程自动同步至存量本机后台；基础镜像和未变资源复用。首次安装资源和升级包不能混为一谈。回退程序版本不等于回退数据库。测试私钥仅用于本机测试更新，正式发布必须另行设计密钥管理和许可审核。

## 安全与兼容边界

工作台网页没有获得启动后台/更新器等 Python 特权桥接接口，这些操作只通过原生菜单执行。下载开启，file:// 访问关闭；普通启动关闭调试端口。--diagnostic-port 仅供本机 UI 验证，不用于常规启动；测试结束已关闭该诊断实例。页面请求与协议、激活门控沿用原逻辑，不发行或伪造正式激活凭证，不代用户签署协议。

state、validation、_trust.py、运行磁盘和任何用户密钥不作为公开源码/发行内容。Windows 单实例锁仅控制本机桌面窗口，后台多 worker 的鉴权与业务一致性仍沿用核心机制，不用桌面内存缓存替代服务端判断。

## 真实验证

打包 EXE 的 WebView2 健康检查通过。更新器/策略既有35项测试通过。物理机窗口内的登录输入与点击、工作台和真实协议门控、受控文件选择、Blob 下载、再次双击复用窗口通过，前端 JS 异常为0。上传/下载这两项是渲染兼容测试，下载由测试 CDP 指定临时目录，不等同于每种业务文件与原生另存为交互均完成验证。

关闭桌面窗口后后台保留；停止本测试 Linux 环境后，再双击正常 EXE 入口可自动冷启动，约42.08秒进入内嵌工作台。后台运行且缓存已准备时约3.47秒打开登录页。均为本机单次测量，不是普遍性能保证。

完整业务、工具、资源评估见 ../docs/windows-preview-assessment.md。真实模型/测绘账号、设备与官网独立激活仍有待测项，不能把入口适配结论称为全功能全部通过。

## 167-10 登录与启动契约

Login.vue与navigationAfterLogin.ts区分认证成功和页面导航完成。正常等待SPA结果；失败/10秒超时或仍在登录页时仅做一次同源文档导航，重新加载被模块加载器缓存为失败的代码。不重复登录，不开放外部重定向，不关闭协议/激活门控。首次窗口不再重复加载HTML，就绪记录需真实Vue表单或工作台挂载，HTTP200本身不足。

frontend_update.py通过私有SSH连接自动同步签名包中的frontend-update.tar.gz。客体实时校验基线/文件哈希，用共享文件锁串行更新，限制路径与文件类型，保护用户配置/数据，保留备份；index.html最后原子替换。较新核心不自动降级。基础初始化尚未完成时先等待ready，再同步前端。本次实际到达原167-8本机实例，Nginx读取挂载产物无需重建或重启。程序回退与核心/前端回退需分别处理。

新EXE实际点击测试覆盖正常登录、首次模块连接失败、受控延迟超时、登录页自身/外部跳转约束；全部通过，原生IsZoomed为true。另有17项导航、11项实际Linux更新边界和35项既有更新/策略检查。可复用导航检查：npm --prefix frontend run test:login-navigation。windows_preview/tests/test_frontend_update.py中Linux文件锁测试需在隔离临时目录的Linux测试环境运行，Windows会明确跳过这些fixture；本次已在本机客体实际完成。详细证据与原始现场触发不确定性见评估。
